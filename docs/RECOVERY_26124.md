# LEGIONFORGE 7.3.5 build 26124 — восстановление и аудит запуска

> **Исторический документ о более ранней сборке.** Для актуального клона `LF-735-01` и последнего `ОШИБКИ.txt` (Criteria Type 213) см. [AUDIT_LF_735_01.md](AUDIT_LF_735_01.md). Указанные ниже источник и результаты 9 тестов относятся к прежней работе, а не к текущему клону.

Исходник: полный клон `https://github.com/andreysf1983-maker/LF-735-full.git`, исходный коммит `114f373f77bb8a08b5f342ee1e0c189310332459`. Все исходные файлы и история Git сохранены. Основание для исправлений — **корневой `ОШИБКИ.txt` именно этого клона**, а не одноимённый документ из более старой сборки.

## Причины сообщений из ОШИБКИ.txt

| Симптом | Подтверждённая причина | Изменение |
|---|---|---|
| 127 614 мс на `Initialize data stores...` без вывода | 240 таблиц DB2 грузились синхронно с единственным сообщением по окончании | `DB2Stores.cpp` сообщает номер и имя **до** загрузки каждой таблицы, время медленных таблиц и каждые 20 файлов. `SpellMgr.cpp` показывает ход подготовки эффектов и `SpellInfo`. Это наблюдаемость, не обещание ускорить чтение диска. |
| ASSERT `Effect < TOTAL_SPELL_EFFECTS`, нужно минимум 262 | Присланный **собранный EXE** содержит старый предел/ASSERT. В клонированных исходниках enum уже равен **262**, а таблица вызовов имеет **262** обработчика, включая безопасную заглушку для ID 261. Исправление исходников без пересборки EXE не может убрать ASSERT. | `build_server.ps1` записывает SHA-256 бинарников и ключевых исходников после сборки. `setup.bat` проверяет EXE до пропуска сборки и после распаковки готового архива. `play.bat` через `check_server_runtime.ps1` не запускает EXE без совпадающего `server/build_sources.json`. **Обязательна новая компиляция**. |
| Не используется `setup_tmp/Win64OpenSSL-3_5_9.exe` | Сборщик ранее искал только `tools/downloads`, потом сразу обращался к сетевому индексу | `build_server.ps1` сначала ищет локальные `Win64OpenSSL-3_*.exe` в `setup_tmp`, `tools/downloads`, корне; проверяет размер, PE и Authenticode либо SHA-256 из `LEGIONFORGE_OPENSSL_SHA256`. Только при отсутствии доверенного локального EXE идёт в сеть; сетевые версии перебираются последовательно. |
| Много предупреждений о DLL в PATH и `OPENSSL_CONF` | Скрипт предупреждал про DLL **другого имени**, игнорируя приоритет каталога EXE; диагностика вызывалась до установки `OPENSSL_CONF` и ещё раз после; «экспорт» искался как обычная строка в файле | Диагностика читает реальную таблицу экспортов PE, исключает дубликаты PATH и DLL, перекрытые локальными, а также не считает отсутствие `OPENSSL_CONF` само по себе падением. `play.bat` устанавливает конфиг до runtime-проверки и запускает диагностику один раз. |

**Дополнительный дефект, найденный аудитом:** отрицательный `SpellEffect.EffectIndex` проходил проверку только верхней границы и превращался в громадный `size_t` при `vector.resize`. Теперь проверяются обе границы и отрицательный `SpellID`; повреждённые записи пропускаются, первые 20 описываются в журнале, общее число сохраняется. Это не «реализует» неизвестные механики: если имеются пропуски, исправьте DB2/обработчик.

## Точные действия на Windows

1. Сделайте резервные копии текущих `server/`, `setup_tmp/` и MySQL. Разверните архив **поверх проекта**, не удаляя локальные базы, карты и настройки. В архиве нет созданных персональных данных пользователя.
2. Если нужен офлайн-OpenSSL, положите настоящий подписанный `Win64OpenSSL-3_5_9.exe` в `setup_tmp/`. Если подпись не проверяется офлайн, сверив SHA-256 с независимым доверенным источником, задайте `LEGIONFORGE_OPENSSL_SHA256` перед сборкой. Файл с неверной подписью и без совпадающего хэша запускаться не будет. Если `tools/openssl` уже полностью установлен, он используется без переустановки. **Остальные зависимости** (Boost, CMake, MSVC, базы ADB) тоже должны быть на диске для работы без интернета.
3. Выполните `build_server.bat` **на Windows с MSVC 2022**. Не сохраняйте прежний `server/worldserver.exe`: исправленные исходники не исправляют уже собранную программу. Дождитесь `server/build_sources.json` и `server/build_info.txt`.
4. Выполните `powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_build_freshness.ps1`. Нужен код 0. Далее `powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_db2_build.ps1`. Проверка заголовков DB2 **не декодирует записи SpellEffect**; они проверяются при загрузке сервером.
5. Выполните `play.bat`. Ожидайте `DB2 [1/240] loading ...` … `Initialized 240 DB2 data stores` → `Loading SpellInfo store...` → открытые порты 1119 и 8085 без ASSERT. Посмотрите `server/logs`, `server/Server.log` и `server/runtime_check.txt`. Завершите тест входом настоящим клиентом 7.3.5 (26124), созданием персонажа и проверкой мира.
6. Если ранее использовались чужие DLL, сверяйте баннер сервера: версия OpenSSL **library** должна соответствовать установленной паре DLL и выбранным для сборки библиотекам. Для несовпадения пересоберите сервер с одним набором OpenSSL.

## Защита от регрессий

- `python tools/audit_regressions.py -v` — 9 автономных проверок: эффект 261, 262 ненулевых слота, GCC-компиляция enum, индексы, прогресс 240 DB2, отпечаток сборки и его использование, локальный установщик, PE-экспорт, кодировки/CRLF. На Linux выполнены успешно; этот тест **не компилирует весь Windows-сервер**.
- `tools/check_db2_build.ps1` дополнительно проверяет размер таблицы обработчиков против `TOTAL_SPELL_EFFECTS` и честно сообщает, что WDC1-содержимое ещё не проверено.
- `.gitattributes` задаёт CRLF для `.bat/.ps1`. После ручного редактирования используйте `python tools/normalize_scripts.py` для CP866+CRLF и UTF-8 BOM+CRLF.
- `server/build_sources.json` обязательно упаковывается штатным `prepare_release.ps1`; чужие или заменённые EXE отклоняются. Не создавайте этот файл вручную — он появляется только после успешной сборки.

## Неустранённые ограничения и риски

- В этом Linux-окружении **нет Windows/MSVC, клиента WoW, извлечённых карт/DB2, MySQL проекта и готовых серверных EXE**. Поэтому реальный Windows-билд, вход клиента и обещание «полностью рабочий игровой мир» здесь подтвердить нельзя; это проверяется указанным Windows smoke-test. Архив содержит полный репозиторий, **не** готовую игровую установку с клиентскими данными.
- В исходном публичном репозитории хранится общая пара `server/bnetserver.cert.pem` / **приватный** `server/bnetserver.key.pem`, а `setup.bat` и `create_admin.bat` задают известный публично GM-пароль. Это **критические унаследованные риски безопасности**. До публикации сервера в интернет необходимо заменить пароль администратора, сменить TLS-ключ на уникальный (`tools/ensure_ssl_cert.ps1 -Force`) и убрать общие секреты из собственной дистрибуции. Данный архив сохраняет все исходные файлы, поэтому эти риски нельзя считать устранёнными упаковкой.
- Данные ADB не являются точным снимком 26124; кастомные DB2 могут содержать неподдерживаемые механики. Ограничители предотвращают аварийное выделение памяти/падение на отдельных некорректных эффектах, но **не гарантируют игровую реализацию всех кастомных эффектов**. Если в логе есть `Skipped ... SpellEffect records`, требуется отдельно проверить игровой контент.
