# LEGIONFORGE 7.3.5 (26124): аудит текущего клона

Источник: **полный `git clone`** `https://github.com/andreysf1983-maker/LF-735-01.git`, ветка `main`, исходный HEAD `4e6333ce51690e7a632333fa4fae3dd635236dc7`. Рабочее дерево до исправлений было чистым; вся история Git сохранена. Проверялся **корневой `ОШИБКИ.txt` этого клона** (1298 строк, завершается ASSERT при загрузке критериев), а не отчёты старых сборок.

## Подтверждённая причина падения

В `ОШИБКИ.txt:1291–1296` после `Loading Criteria Lists...` сервер аварийно завершился на `CriteriaHandler.cpp:2388`: `criteriaEntry->Type < CRITERIA_TYPE_TOTAL`, фактически `Type = 213`, `CRITERIA_TYPE_TOTAL = 213`. Enum ядра знает типы `0..212`; назначать типу 213 придуманную механику или просто расширять массив до 214 **нельзя**. Клиентские данные содержат записи вне диапазона ядра.

| Изменение | Результат / границы |
|---|---|
| `core/src/server/game/Achievements/CriteriaHandler.cpp` | Вместо фатального ASSERT неизвестные типы пропускаются **до индексации четырёх массивов**. Некорректный `StartEvent` таймерного критерия также пропускается до индексации. В журнале первые 20 ID/значений каждого вида и итоговые счётчики. |
| `CriteriaHandler.cpp`, `IsCompletedCriteriaTree` | Узел, ссылающийся на отсутствующий/пропущенный критерий, не считается выполненным (в том числе `SINGLE_NOT_COMPLETED`); это предотвращает ошибочную выдачу достижения. |
| `tools/check_build_freshness.ps1` | В отпечаток сборки добавлены `CriteriaHandler.cpp/.h`, `ScenarioMgr.cpp`, `DBCEnums.h`. Старые EXE и старые манифесты отклоняются: **нужна сборка через `build_server.bat`**. |
| `tools/legion_db2/audit_criteria_db2.py` | Read-only предварительная проверка строк `Criteria.db2` тем же декодером WDC1 и метаданными, что используются в проекте; читает лимиты из C++ заголовка. Коды: `0` — нет отклонений, `1` — несовместимые строки, `2` — файла нет/он не читается. Результаты доступны как текст или JSON (`--json`). Это проверка **исходного DB2**: наложенные SQL hotfixes учитываются уже сервером. |

**Важно:** пропуск несовместимых записей предотвращает этот ASSERT, но не добавляет игровых механик типа 213 и не доказывает совместимость остальных данных. Для полноценной игры используйте карты и DB2, извлечённые из собственного **чистого клиента 7.3.5 build 26124**.

## Найдено дополнительно

1. `ScenarioMgr::LoadScenarioPOI` выделял память по максимальному `CriteriaTreeID` из SQL (`vector.resize(id + 1)`) и индексировал отрицательные `Idx1`/ID. При повреждённой базе это потенциальное выделение гигантского массива или обращение за границы. Заменено на разреженный `map<pair<ID, Idx1>, vector<point>>`, несуществующие деревья/отрицательные значения и определения без точек пропускаются. Память пропорциональна числу реальных точек.
2. **Baseline сам нарушал заявленные правила кодировок:** `.gitattributes` не содержал правил CRLF, 58 отслеживаемых Windows-скриптов после `git clone` имели LF; 1 из 9 исходных регрессионных тестов не проходил. Добавлены `eol=crlf` для `.bat/.cmd/.ps1`, в рабочем дереве восстановлены CRLF без изменения кодировок. `.bat` остаются CP866, `.ps1` — UTF-8 с BOM.
3. В логе ещё **1609 пропущенных несовместимых записей SpellEffect** (в т.ч. SpellID 304000–305010), десятки подземелий более позднего дополнения без входов и ссылки на отсутствующие лут/предметы. **Это несовместимые DB2/ADB/SQL, а не подтверждение исправления игрового контента**. Нельзя автоматически добавлять фиктивные предметы, входы или обработчики заклинаний. Сверяйте свои DB2, чистую ADB и выполняйте игровой smoke-test.
4. Загрузка 240 DB2 в присланном логе заняла ~114 сек; `BroadcastText.db2` — ~78 сек. Это данные и I/O конкретной машины, а не замер производительности исправленного билда. Дальнейшая оптимизация только после профилирования на реальном сервере; здесь не менялись форматы DB2 или многопоточность загрузки.
5. **Критические унаследованные риски безопасности (не устранены в полном клоне):** публичный приватный ключ `server/bnetserver.key.pem` и общедоступный GM-пароль, который `setup.bat` и `create_admin.bat` снова устанавливают как `legionforge`. Не открывайте порты в интернет до смены пароля **после последнего запуска setup/create_admin**, генерации собственной TLS-пары (`tools/ensure_ssl_cert.ps1 -Force`), удаления распространённого ключа из своей публичной дистрибуции и ограничения доступа к MySQL. Исходный публичный репозиторий сохраняется в полном архиве по требованию; **архив не является защищённым production-релизом**.
6. `docs/RECOVERY_26124.md` описывает старые симптомы и другой исходный URL: актуальные для этого клона сведения в **этом** документе.

## Воспроизведение проверок (без Windows-данных)

```text
python tools/audit_regressions.py -v
python -m unittest discover -s tools/legion_db2 -p test_audit_criteria_db2.py -v
python tools/legion_db2/audit_criteria_db2.py --dbc server/data/dbc/enUS --json
git diff --check
```

На Linux: **13/13** регрессионных тестов и **4/4** теста CLI/синтетического WDC1 успешно; отрицательные индексы, границы enum, содержимое фикстуры, пропуск таймеров и кодировки проверены. Команда проверки реального DB2 здесь возвращает `2`, потому что `server/data/dbc/enUS/Criteria.db2` **отсутствует**. Отдельный Python CLI **не компилирует весь мир**, тесты не подтверждают игровую реализацию.

## Что сделать на Windows перед выпуском

1. Сохранить локальные MySQL-базы, каталоги `server/data`, `setup_tmp`, свои конфиги и сертификаты. Распаковать архив с сохранением структуры; он содержит исходники и историю Git, но **не содержит WoW-клиента, карт/DB2 и собранных worldserver/bnetserver.exe**.
2. Извлечь данные **своего** 7.3.5 build 26124, затем запустить `python tools\legion_db2\audit_criteria_db2.py --dbc server\data\dbc\enUS` и `powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_db2_build.ps1`. Первая команда проверяет строки критерия, вторая — сигнатуры/заголовки и другие лимиты; обе полезны. Если есть тип 213, очищайте исходные клиентские данные, а не ослабляйте проверку.
3. Собрать `build_server.bat` на Windows/MSVC 2022; проверить `tools\check_build_freshness.ps1`. Никогда не оставлять старый `server/worldserver.exe` или чужой `build_sources.json`.
4. Запустить `setup.bat` / `play.bat` в тестовой среде. Нужны лог `Loaded ... criteria`, отсутствие ASSERT/выхода процесса, работающие `bnetserver`/`worldserver`, вход игрового клиента, создание персонажа, проверка достижений, сценариев, лута и маршрутов. Проверить логи на **новые** ошибки: пропуск типа 213 сам по себе ещё не признак исправления данных.
5. **После последнего setup** сменить пароль GM и TLS-ключ. Пока этого не сделали — только изолированная локальная сеть, никаких публичных портов.

В текущем Linux-сандбоксе нет Windows/MSVC, WoW-клиента, игровых DB2/карт, установленной игровой MySQL и собранных игровых EXE. **Полностью работающий сервер или успешный вход в игру в этих условиях не доказаны.**
