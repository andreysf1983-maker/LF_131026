# Аудит: что отключено, что не доделано, и можно ли добавить новые расы

Дата аудита: 2026-10. Проверено по исходникам ядра, конфигов и по **реальным данным**
чистого дампа ADB_735.10 (строки импортированы в тестовую MariaDB 10.11 и проверены запросами,
а не "на глаз"). Все утверждения ниже имеют ссылку на файл/строку или на результат запроса.

---

## 1. Короткий ответ про Харанир, Вульпер и Механогномов

**На клиенте 7.3.5 build 26124 их добавить нельзя.** Причина не в настройках сервера, а в клиенте:

1. Ядро знает расы только до 30: `RACE_NIGHTBORNE=27 … RACE_LIGHTFORGED_DRAENEI=30`,
   `MAX_RACES 31` (`core/src/server/game/Miscellaneous/SharedDefines.h:167-174`).
2. При загрузке `race_unlock_requirement` ядро сверяет каждую расу с **клиентским** `ChrRaces.db2`:
   `ChrRacesEntry const* raceEntry = sChrRacesStore.LookupEntry(raceID); if (!raceEntry) { … "Race %u … does not exists, skipped." }`
   (`core/src/server/game/Globals/ObjectMgr.cpp:9948-9952`). Нет строки в DB2 клиента — раса отбрасывается.
3. Сервер читает DB2 из файлов, извлечённых из клиента: `db2Path = dataPath + "dbc/"`
   (`core/src/server/game/DataStores/DB2Stores.cpp:480`), всего 242 хранилища. То есть набор
   рас/моделей/форм определяет клиент, а не сервер.
4. Внешность — это не только строка DB2: нужны M2-модель, текстуры, скелет и анимации. Они лежат
   в CASC клиента. Механогномы/Вульперы/Харанир появились в 8.3 и 9.0.1, в CASC 7.3.5 их файлов нет.
   Передать их через DB2-хотфикс сервера невозможно: хотфикс меняет значения строк, а не файлы моделей.

**Как проверить именно ваш клиент** (не на слово, а по факту):

```bat
python tools\legion_db2\audit_races_forms.py
```

Скрипт читает `server\data\dbc\enUS\ChrRaces.db2`, `CharSections.db2`, `CharStartOutfit.db2`,
`SpellShapeshiftForm.db2`, `CreatureDisplayInfo.db2` тем же парсером, которым пользуется
DB-stitcher проекта (`tools/legion_db2/wdc1.py` + метаданные ядра), и пишет отчёт
`logs/race_form_audit.md`. Если в отчёте появятся расы с ID ≥ 31 — значит у вас клиент не 26124
(или DB2 подменены), и к этому серверу он не подключится: протокол и опкоды 7.3.5.

Что потребовалось бы для Харанир/Вульпер/Механогномов теоретически: порт моделей и анимаций из
клиента 8.3/9.x, сборка кастомных DB2 (ChrRaces, CharSections, CharStartOutfit,
CreatureDisplayInfo/Extra, CreatureModelData, CharacterFacialHairStyles), правка CASC клиента,
расширение `Races`/`MAX_RACES`/масок в ядре, стартовые данные и расовые умения. Это отдельный
проект уровня "свой клиент", а не доработка сервера; в рамках 26124 он не окупается.

## 2. Что РЕАЛЬНО было отключено: союзные расы Legion (27-30)

Это и есть "начато, но не включено". Данные в чистом ADB_735.10 **полные** (проверено запросами
по импортированному дампу):

| ID | Раса | Старт (map/zone) | Классов | player_levelstats | Стартовый предмет | Панель умений |
|---|---|---|---|---|---|---|
| 27 | Ночнорождённые | 1220 / 7637 (Suramar) | 7 (1,3,4,5,8,9,10) | 770 строк | 7 (маунт) | **0** |
| 28 | Таурены Крутогорья | 1220 / 7731 (Highmountain) | 5 (1,3,7,10,11) | 550 строк | 5 (маунт) | **0** |
| 29 | Эл'рейские (Void Elf) | 1865 | 7 (1,3,4,5,8,9,10) | 770 строк | 7 (маунт) | **0** |
| 30 | Озарённые дренеи | 1860 | 5 (1,2,3,5,8) | 550 строк | 5 (маунт) | **0** |

Классы старта совпадают с `player_levelstats` — это важно: при несовпадении worldserver аварийно
завершается (`ObjectMgr.cpp:3680-3684`, "Race %i Class %i Level 1 does not have stats data!").

Мешали ровно две вещи:

1. **База:** `race_unlock_requirement.expansion = 7` (BfA) для рас 27-30, тогда как сервер Legion:
   `Expansion = 6` в `server/worldserver.conf.dist:701`, а `CharacterHandler.cpp` считает
   `raceUnlock.HasExpansion = GetAccountExpansion() >= requirement.Expansion`. Итог: клиент
   получает "раса не открыта".
2. **Ядро:** `charEnum.IsAlliedRacesCreationAllowed = GetAccountExpansion() >= EXPANSION_BATTLE_FOR_AZEROTH;`
   (`core/src/server/game/Handlers/CharacterHandler.cpp:338`). Флаг уходит в клиент
   (`CharacterPackets.cpp:208`) и открывает раздел союзных рас в UI.

Поднимать expansion аккаунта до 7 **нельзя**: `GetMaxLevelForExpansion(7)` возвращает 0
(`SharedDefines.h:105-127`) — ветки BfA в ядре нет, потолок уровней сломается.

### Что сделано в этом репозитории

| Изменение | Файл | Эффект |
|---|---|---|
| `expansion` 7 → 6 для рас 27-30 (+ строки, если их нет) | `sql/48_legion_allied_races.sql` | клиент считает расы открытыми |
| Заполнение стартовой панели умений из "родительской" расы того же класса | `sql/49_legion_allied_races_hotbar.sql` | персонаж не появляется с пустой панелью |
| Одна строка ядра: `EXPANSION_BATTLE_FOR_AZEROTH` → `EXPANSION_LEGION` | `CharacterHandler.cpp:338` | раздел союзных рас показывается в UI |
| Откаты | `sql/48_…_rollback.sql`, `sql/49_…_rollback.sql` | вернуть всё назад |
| Патчи подключены к установщику и к запуску | `setup.bat`, `apply_play_sql.ps1` | применяются автоматически, идемпотентно |

Панель умений копируется от родителей (27←10, 28←6, 29←10, 30←11), **расовые умения родителя
исключаются** по `playercreateinfo_cast_spell` (racemask = 2^(race-1)) — чужая расовая кнопка
на панель не попадает. Копируются только классы, доступные новой расе (сверка с `playercreateinfo`).

**Проверено на тестовой MariaDB 10.11** с настоящими DDL и строками ADB: оба патча применены
дважды (идемпотентны: 4 строки unlock, 80 строк панели), наборы классов совпали со стартовыми,
запрос на "утечку" расовых умений родителя вернул пустой результат.

**Что нужно сделать вам:** пересобрать ядро (`build_worldserver.bat`) — без этого строка
`CharacterHandler.cpp` не попадёт в `worldserver.exe`, и клиент по-прежнему не покажет раздел.
SQL-патчи применит `setup.bat` или `play.bat`.

### Ограничение, которое осталось

Новый персонаж союзной расы создастся **1-го уровня**, а не 110-го как в retail: `Player::Create`
берёт стартовый уровень из `character_template` и `CONFIG_START_GM_LEVEL`
(`Player.cpp:559+, 642-680`), а `ChrRaces.StartingLevel` ядро при создании не читает
(`sChrRacesStore` используется только в `ObjectMgr` и `BotAI`). Если нужен старт со 110-го —
это отдельная правка (уровень + стартовая экипировка/умения под 110).

## 3. Друид-формы и облики из новых дополнений

Форма превращения = строка `SpellShapeshiftForm.db2` (`Name`, `CreatureDisplayID1..4`) +
`CreatureDisplayInfo.db2` + сама модель в CASC клиента. Сервер читает оба файла из
`server/data/dbc` (те же 242 хранилища). Поэтому:

- **Формы, которые есть в клиенте 7.3.5, работают** — их список покажет
  `tools/legion_db2/audit_races_forms.py` вместе с проверкой, что каждый `CreatureDisplayID`
  существует в `CreatureDisplayInfo.db2`.
- **Форм из 8.x/9.x в клиенте 26124 нет**: ни строк DB2, ни моделей. Сервер не может выдать то,
  на что нельзя сослаться; ссылка на несуществующий дисплей — это риск краша клиента. В проекте
  уже есть такой пример: `TPL3` в `docs/stability/MASTER-INVENTORY.md` — `modelid2=68486`
  "doesn't exist (can crash the client)".
- Облики артефактов Legion (то, что реально есть в 7.3.5) сервер поддерживает:
  `sArtifactAppearanceStore`, `sArtifactAppearanceSetStore` и др. (`DB2Stores.cpp:45-55`).

Вывод: "облики друидов из новых дополнений" на 26124 — то же ограничение, что и расы: нужен клиент
с этими моделями. Внутри Legion-контента (артефакт-облики, существующие формы) работать можно.

## 4. Отключено в конфигурации (включается без кода)

| Параметр | Значение | Файл:строка | Что даёт включение |
|---|---|---|---|
| `mmap.enablePathFinding` | 0 | `worldserver.conf.dist:418` | навигация NPC по mmaps (нужны сгенерированные mmaps; `extract_maps.bat` их делает) |
| `AllowTwoSide.Interaction.Group/Guild/Auction/Channel/Calendar`, `AllowTwoSide.Trade` | 0 | `:1514-1554` | взаимодействие между фракциями |
| `Instance.IgnoreLevel`, `Instance.IgnoreRaid` | 0 | `:962,970` | вход в подземелья без ограничений по уровню/рейду |
| `InstanceMapLoadAllGrids` | 0 | `:343` | предзагрузка всех сеток карты (память vs лаги) |
| `CharacterCreating.Disabled.RaceMask` / `ClassMask` | 0 | `:782,801` | ничего не заблокировано (можно блокировать расы/классы масками) |
| `Expansion` | 6 | `:701` | верно для 7.3.5; не менять (см. §2) |

Всего в `worldserver.conf.dist` 169 параметров со значением `0` — часть - переключатели, часть - режимы.
`patch_conf_paths.ps1`/`mysql_helper.ps1` правят только пути и подключение к БД.

## 5. Начато, но не доделано (крупное)

### 5.1 Не применяются SQL-обновления world/hotfixes
- `sql/legionforge/old/world` — **472 файла**, `sql/legionforge/old/hotfixes` — **22 файла**.
  Их не применяет ничто: `apply_schema_updates.ps1` принимает только `auth|characters`
  (`ValidateSet('auth','characters')`, строка 15), а `setup.bat` вызывает его лишь для этих двух баз.
  Там лежат, например, `2017_12_20_03_world_suramar_casual.sql`, `2018_01_13_03_world_wandering_island.sql`,
  `2018_02_19_03_world_playercreateinfo.sql`, `2018_02_27_02_world_allied_races_mounts.sql`,
  `2018_04_06_03_world_playercreateinfo_action.sql`.
- `sql/updates/world/master` — **189 файлов**, `sql/updates/hotfixes/master` — **12 файлов**: тоже не применяются.
- **Важно:** применять их "оптом" нельзя. ADB_735.10 — снимок от 17.08.2018, часть этих обновлений
  в нём уже есть (проверено: стартовые строки рас 22/24-30 и маунты союзных рас присутствуют),
  поэтому слепой прогон даст дубли и конфликты. Нужен точечный подход: проверять конкретную
  нехватку данных и добавлять идемпотентный патч (как сделано в §2).
- Единственный SQL-файл проекта, который не применяется намеренно: `sql/16_quest_audit_queries.sql`
  (это справочные запросы аудита, не патч).

### 5.2 По инвентарю стабильности проекта (`docs/stability/MASTER-INVENTORY.md`)
- **ENV7**: 295 `ScriptName` в БД не имеют C++-скрипта (например `instance_mogu_shan_vault`).
- **ENV8**: 1917 отклонённых SQL-запросов (пустая строка в целочисленный `difficulty`), источник не найден.
- **TPL1-TPL4**: 36 кастомных шаблонов с `unit_class=0`, фракцией 35 и несуществующим `modelid2=68486`;
  ни одного спавна в мире — контент недоступен.
- **CMP1-CMP19**: система наёмных компаньонов сломана (фракция 35 → цели не находятся, `SetHealth`
  вместо урона, дезпаун через 30 минут, записи-призраки в лимите из 4).
- **BOT1-BOT9**: класс-боты доступны только через автозаполнение подземелий; у 47/50 способностей
  урон ~1 (масштабируется от SP существа, которое равно 0).
- **PVP1-PVP2**: `npc_bg_bot_AI` объявлен, но не создаётся; `AIM_Initialize()` сбрасывает агрессию.
- **ADV1**: скрипт "авантюриста" скомпилирован и зарегистрирован, но ни один шаблон его не использует (мёртвый код).
- **W2-W5**: призыв питомца чернокнижника не работает, причина не установлена (нет логирования кастов).
- **Q2-Q8, Q12**: фазирование стартовых зон почти пустое (Калимдор: 6 из 60691 существ в фазе),
  ~1750 целей квестов без спавна.
- **X1-X8**: не проверены вовсе (охота/петомы, грядки гарнизонов, мировые квесты, экономика, AH, гильдии).
- Инвентарь ссылается на `docs/PROBLEM-AREAS.md` — **этого файла в репозитории нет**.

### 5.3 Мелкие дыры в данных (найдено этим аудитом)
- Пандарены Альянса/Орды (25, 26): `playercreateinfo_action` = 0 строк → пустая панель умений
  (у нейтрального пандарена 24 строки есть). Лечится так же, как §2: копирование от расы 24.
- `playercreateinfo_spell` пуст для всех рас — расовые заклинания выдаются через
  `playercreateinfo_cast_spell` (racemask). Для рас 27-30 строк с масками нет, то есть
  **расовые умения союзных рас не выдаются** (Arcane Pulse, Entropic Embrace и т.д.).
  Чтобы добавить: найти ID умений в `Spell.db2` клиента (`tools/legion_db2/lookup_spells.py`)
  и добавить строки в `playercreateinfo_cast_spell` с масками 2^26…2^29. Намеренно не сделано
  здесь: ID умений нельзя брать из головы, а в дампах ADB их нет (`spell` в hotfixes — 4 строки).

## 6. Что сделать по шагам

1. Пересобрать ядро: `build_worldserver.bat` (нужно для строки `CharacterHandler.cpp`).
2. Применить патчи: `setup.bat` (или `play.bat` — патчи идемпотентны и применяются при каждом запуске).
3. Проверить клиент: `python tools\legion_db2\audit_races_forms.py` → `logs\race_form_audit.md`.
   Убедиться, что расы 27-30 есть в `ChrRaces.db2` и у них ненулевые `CharSections`/`CharStartOutfit`.
4. Создать персонажа союзной расы в клиенте (раздел "Allied Races" на экране создания).
5. Если расы не видно — смотреть `Server.log` на строки `Race %u … does not exists, skipped`
   (это значит, в клиентском `ChrRaces.db2` такой расы нет).

## 7. Реалистичные следующие шаги (по убыванию отдачи)

1. Расовые умения союзных рас (`playercreateinfo_cast_spell`) — нужны ID из `Spell.db2` клиента.
2. Панель умений пандаренов 25/26 — копия от расы 24 (10 минут работы).
3. Старт союзных рас со 110-го уровня — правка `Player::Create` + стартовый набор.
4. `mmap.enablePathFinding = 1` после генерации mmaps — оживит навигацию NPC.
5. Точечное применение нужных файлов из `sql/legionforge/old/world` (472 шт.) — только по факту
   найденной нехватки данных, с идемпотентными патчами и откатами.
6. ENV7 (295 скриптов без реализации) — самый большой объём работы по контенту.
