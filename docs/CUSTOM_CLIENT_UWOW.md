# Кастомный клиент (UWoW 7.3.5 build 26124) и сервер LegionForge

## 1. Почему «[OK] server\data уже содержит проверенные maps, dbc и vmaps» — это ловушка

`check_game_data.ps1` отвечает ровно на один вопрос: **хватит ли данных, чтобы
worldserver не упал при старте**. Он считает плитки карт, ищет `Map.db2` и
`*.vmtree`. Если вы положили `data` из другой сборки — порог пройден, и
`extract_maps.bat` печатал «Извлечение пропущено».

При этом **клиент никто не читал**. Весь кастом вашего клиента (новые расы,
карты новых дополнений, изменённые db2, свои модели) на сервер не попадал
никогда — отсюда «раса есть в окне создания, но персонаж не создаётся»,
«карта грузится в пустоту», «NPC не ходят на новой локации».

## 2. Что сделано

| Шаг | Инструмент | Результат |
|-----|-----------|-----------|
| Сверка клиента и `server\data` | `check_client_delta.ps1` | `reports/client_delta.json` + `.md`: какие db2 есть в клиенте и отсутствуют на сервере, какие отличаются, какие расы/классы кастомные, отличается ли `Map.db2` |
| Доизвлечение без потери готовых данных | `extract_delta.ps1` | копирует в `server\data` **только недостающие** файлы (maps, dbc, Cameras, gt, vmaps) и генерирует mmaps только для новых карт |
| Включение кастомных рас на сервере | `sql/50_uwow_custom_races.sql` | стартовые позиции, `player_levelstats`, предметы, заклинания, панель команд и снятие гейта дополнения для рас 31, 32, 34, 35, 36, 37 |
| Союзные расы Legion (27–30) | `sql/48_legion_allied_races.sql` | уже было в проекте |

`extract_maps.bat` больше не «просто пропускает» шаг: если данные на месте,
он запускает дельта-проверку и предлагает меню:

```
 [1] Ничего не делать (данные в порядке)
 [2] Доизвлечь ТОЛЬКО недостающее из клиента  <- для кастомных клиентов
 [3] Полное переизвлечение с нуля
```

## 3. Порядок действий на кастомном клиенте

```bat
rem 1. Что именно есть в клиенте, но нет на сервере (3-5 минут, читает только db2)
powershell -NoProfile -ExecutionPolicy Bypass -File check_client_delta.ps1

rem 2. Доизвлечь недостающее (карты/vmaps могут занять часы, ничего не затирается)
powershell -NoProfile -ExecutionPolicy Bypass -File extract_delta.ps1 -MmapsMode new

rem 3. Включить кастомные расы в world-базе
tools\mysql\server\bin\mysql.exe -uroot world < sql\50_uwow_custom_races.sql
```

## 4. Почему изменённые db2 не подменяются автоматически

Ядро 7.3.5 сверяет каждый db2 со своими метаданными
(`core/src/server/game/DataStores/DB2Metadata.h`): сигнатура `WDC1`,
`LayoutHash`, `MaxId`. Файл из клиента более нового формата (`WDC2`/`WDC3`)
или с другим набором полей приводит к немедленному `ASSERT`, например:

```
DB2Stores.cpp:745 ASSERTION FAILED:
BATTLE_PET_SPECIES_MAX_ID (2164) must be equal to or greater than 5004
```

Поэтому `extract_delta.ps1` кладёт расходящиеся файлы в
`server\data\dbc_client_delta` и **не трогает** рабочие. Подменять их можно
только после `tools\check_db2_build.ps1`, то есть когда `LayoutHash` совпал,
а константы ядра подняты под новые `MaxId`.

## 5. Кастомные расы: что требуется от ядра

Данные в world-базе — только половина дела. Чтобы клиент показал расу и
позволил создать персонажа:

1. `race_unlock_requirement.expansion = 6` (делает SQL-файл).
2. `core/src/server/game/Handlers/CharacterHandler.cpp` —
   `IsAlliedRacesCreationAllowed` должен срабатывать при
   `GetAccountExpansion() >= EXPANSION_LEGION`.
3. Для рас **вне** диапазона enum `Races` (`SharedDefines.h`) дополнительно
   нужны:
   - расширение `RACEMASK_ALL_PLAYABLE` (маска 64-битная, расы >32 требуют
     `UI64LIT(1) << (race - 1)`);
   - запись в `ChrRaces.db2` клиента (она уже есть — иначе расы не было бы
     в окне создания);
   - стартовая экипировка и `player_levelstats` (их клонирует SQL-файл).

`check_client_delta.ps1` печатает список ID, которых нет в enum `Races`
ядра — это и есть точный перечень того, что надо добавить в `SharedDefines.h`
перед пересборкой.

## 6. Полезные файлы отчётов

- `reports/client_delta.json` — машинно-читаемая дельта (её читает панель управления).
- `reports/client_delta.md` — тот же отчёт для человека.
- `reports/extract_delta.json` — что именно было докопировано в последний раз.
- `server/logs/extract_delta_*.log` — полный журнал доизвлечения.
