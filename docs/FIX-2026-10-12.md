`DB2Stores.cpp` — найдены **7 мест**, где индексы из DB2 писались в фиксированные массивы под защитой только ASSERT (тот же класс, что краш №1; часть уже чинилась ранее для PvpTalent/Talent, эти были пропущены): `ChrClassesXPowerTypes` (чтение массива **до** ASSERT — UB), `ChrSpecialization`, `CharBaseSection`, `CharSections`, `ItemClass`, `PowerType`, `ItemChildEquipment`. Везде: лог + пропуск записи.

**Правило на будущее (не допускать впредь):** любое значение из DB2/SQL/пакета клиента, используемое как индекс фиксированного массива, проверяется `if (x >= SIZE) { LF_LOG_ERROR(...); continue; }` **до** использования. ASSERT — только для инвариантов самого кода, никогда для внешних данных.
