# Почему .bat-файлы «мигали и закрывались» и что исправлено

| Причина | Исправление |
|---|---|
| LF-окончания строк (из-за `* text=auto` в `.gitattributes`). `cmd.exe` с LF неверно находит метки `goto :X` / `call :X`. | Все `.bat`/`.ps1` переведены в CRLF; `.gitattributes` закрепляет `eol=crlf`. |
| UTF-8 + `chcp 65001`: cmd читает bat побайтово, многобайтовая кириллица сбивает смещения меток. | `.bat` в кодировке CP866 + `chcp 866` (1 символ = 1 байт). Русские сообщения сохранены. |
| `echo ... (код 5)` внутри блоков `( ... )`: незаэкранированная `)` закрывает блок, cmd падает с синтаксической ошибкой. | `)` в таких `echo` экранированы `^)`. |
| `echo ... %MYSQL%` внутри блока при пути `C:\Program Files (x86)\...` — та же проблема. | Пути в `echo` внутри блоков выводятся через `!VAR!` (или `%VAR:)=^)%`). |
| `.ps1` без BOM читаются Windows PowerShell 5.1 как ANSI. | Все `.ps1` — UTF-8 с BOM. |

Утилита `tools\normalize_scripts.py` приводит скрипты к нужному виду и идемпотентна.

## Базы данных
Вручную из `sql\base\` нужны только `auth.sql` и `characters.sql`. Если world/hotfixes пусты,
`get_databases.ps1` получает чистый официальный ADB_735.10 и создаёт `ADB_world.sql` /
`ADB_hotfixes.sql`. RAR распаковывается RARLAB UnRAR (7-Zip не умеет метод m3 в этом архиве);
импортируется только в пустые world/hotfixes базы. Смотрите `docs\ADB_DATABASES.md`.


## Клиент WoW и уже готовые карты

`setup.bat` не ищет клиент на старте. Перед извлечением он запускает `check_game_data.ps1` для
`server\data` и проверяет не менее 200 файлов `maps\*.map`, покрытие обязательных континентов Vanilla–Legion, `dbc\Map.db2` и не менее 50 файлов `vmaps\*.vmtree`.
Если всё найдено, клиент не запрашивается и карты не извлекаются повторно; патч клиента также пропускается,
если сам клиент не был найден. Если обязательные данные отсутствуют, setup ищет клиент в `WoW_Client` и
затем спрашивает путь. Отдельный `extract_maps.bat` использует ту же проверку и завершает работу без
повторного извлечения. `mmaps\*.mmtile` рекомендованы для навигации NPC, но необязательны.

## UNBLOCK.bat и кодировка setup_log.txt

`UNBLOCK.bat` больше не обращается к неустановленной переменной `$env:LF_ROOT`: PowerShell берёт папку
из текущего каталога, в который bat переходит через `cd /d "%~dp0"`.

`setup_log.txt` теперь создаётся в UTF-8 с BOM. Все записи из batch проходят через
`tools\write_setup_log.ps1`, который конвертирует вывод CP866 из временных файлов и добавляет его
в UTF-8 лог. Поэтому кириллица не должна превращаться в «кракозябры» в Блокноте.
